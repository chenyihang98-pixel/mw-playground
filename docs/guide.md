# 遊び方と設定

## 操作

制限時間内に宝石を必要な数だけ集めればクリア、時間切れで失敗です。巡回している守衛に触れると 10 秒引かれます。そのあと 2 秒間は、触れても引かれません。

| 操作 | キー |
|---|---|
| 移動 | W / A / S / D |
| 走る | Shift を押しながら |
| ジャンプ | Space |
| 視点 | マウスを動かす。矢印キーでも回せます |
| 一時停止 / 再開 | Esc または P |

- 高台にはジャンプでは届きません。スロープを歩いて上ります
- 「スタート」を押すと、マウスが画面の中に固定されます。Esc で固定が外れ、同時に一時停止します
- メニューはキーボードだけでも操作できます。Tab で移動、Enter か Space で決定、Esc でパネルを閉じます

## 言語

画面は日本語・英語・中国語の 3 つです。

- スタート画面の下と一時停止メニューに、言語の選択があります。選ぶと保存して再読み込みします。名簿、保存済みのステージ、ミュートの設定はそのまま残ります
- プレイ中は、Esc で一時停止してから切り替えます
- URL に `?lang=ja`、`?lang=en`、`?lang=zh` を付けると、そのときだけその言語で開きます。保存した選択は変わりません
- まだ選んでいなければ、ブラウザーの言語に合わせます。日本語なら日本語、中国語なら中国語、それ以外は英語です
- ファイル名、名簿の名前、保存したステージのタイトルは、入力したまま表示します。モデルが書く文と、工房のサービスが返す説明は、今のところ中国語のままです

## キャラクターの読み込み

「キャラクター読み込み」でファイルを選ぶか、ウィンドウにファイルをドラッグします。

| 形式 | |
|---|---|
| `.glb` | ボーンとアニメーション付きのキャラクター。基本はこれです |
| `.obj` `.stl` `.ply` | 静的モデル。既定のマテリアルで表示します（OBJ の MTL は読みません） |

大きすぎるファイルはまず注意が出て、さらに大きいと読み込みません。

| | 注意が出る | 読み込まない |
|---|---|---|
| ファイルサイズ | 50 MB 超 | 150 MB 超 |
| 三角形 | 30 万超 | 100 万超 |
| ボーン | | 256 超 |
| アニメーションクリップ | | 64 超 |
| テクスチャの一辺 | | 8192 超 |

外部ファイルを参照している GLB と、Draco・Meshopt・KTX2 で圧縮した GLB も読めません。壊れたファイルは「読み込み失敗」と出るだけで、いまの主人公とシーンはそのままです。

読み込むと右側にカードが出ます。ここでできること：

- 表示上の身長を変える（1.2〜2.4 m、既定は 1.75 m）。見た目だけで、当たり判定は変わりません
- 向きが違うときは左右に 90° 回す
- 各クリップが何に割り当てられたか（待機・歩き・走り・ジャンプ・その他）を見て、違っていれば手で直す。ループするかどうかも変えられます
- クリップ自体が移動を含んでいるときは「水平移動を固定」にチェックを入れる
- 「名簿に追加」、またはそのまま「主人公にする」

足りないモーションはこう補います。走りがなければ歩きを速める。歩きがなければ走りを遅くする。待機がなければ歩きの最初のフレーム。移動のモーションが 1 つもないとき（静的モデルも含む）は、モデル全体を上下に揺らして動かします。

## 名簿

- ブラウザー（IndexedDB）に保存します。20 人まで。同じファイルは 2 回入りません
- 役割は 5 つ：主人公、守衛、主人公兼守衛、仲間、登場しない。主人公は 1 人だけ、仲間は 3 人まで
- 守衛にしたキャラクターは、ステージにいる守衛の見た目を置き換えるだけです。守衛の数とルートは変わりません。人数が足りない分は既定の人形になります
- 仲間は主人公の斜め後ろをついてきます。マップとだけ衝突し、宝石は拾わず、守衛にも捕まりません。離れすぎると近くに戻ってきます
- 読み込んだキャラクターを同時に出せるのは 12 体までです
- ブラウザーが保存を許可していないときも名簿は使えます。ただしページを閉じると消えます

## ステージ

- **内蔵**：手作りのマップが 3 つ（草原と、テスト用の小さなステージ 2 つ）、生成して固定したものが 3 つ
- **ランダムで 1 つ**：プログラムがランダムに仕様書を書き、生成して検査します。まずプレビューが出て、確定するまで保存されません
- **保存済み**：確定したランダムのステージと工房のステージ。読み込みと削除ができます。遊び直すときは保存した配置をそのまま使い、作り直しません

ステージごとに難しさの目安（ゆったり・ふつう・きつめ）が出ます。走って全部集めるのにかかる時間と、制限時間を比べたものです。守衛と回り道は計算に入っていません。

工房で作ったステージには、チェックを入れた人物だけが登場します。誰にもチェックを入れなければ仲間はなし、守衛は既定の人形です。主人公は名簿のとおりです。

## レベル工房

`npm run dev:workshop` で、ゲーム（ポート 5173）と工房のローカルサービス（ポート 8790）が一緒に起動します。サービスは 127.0.0.1 でだけ待ち受けます。

- 最初の生成の前に、モデルを VRAM に読み込みます。ふつうは数秒ですが、長く使っていなかったあとは数十秒かかることがあります
- 生成中は「生成をやめる」で止められます
- プレビューには、使ったモデル、1 回で通ったか何回直したか、プログラムが条件を調整したかどうかが出ます
- プレビューのあとは「確定」「一文を書き直す」「破棄」のどれかです

### 設定

環境変数で設定します。プロジェクト直下の `.env` に書いてもかまいません。

| 変数 | 既定値 | |
|---|---|---|
| `MW_LLM_PROVIDER` | `ollama` | `ollama`、`openai`、`off` のどれか |
| `MW_OLLAMA_BASE_URL` | `http://127.0.0.1:11434` | Ollama のアドレス |
| `MW_OLLAMA_MODEL` | `qwen3.5:9b-q4_K_M` | モデル名。自動ではダウンロードしません |
| `MW_OLLAMA_NUM_CTX` | `8192` | コンテキスト長 |
| `MW_OPENAI_BASE_URL`、`MW_OPENAI_MODEL`、`MW_OPENAI_API_KEY` | なし | OpenAI 互換 API（偽サーバーで試しただけです） |
| `MW_WORKSHOP_PORT` | `8790` | サービスのポート |
| `MW_WORKSHOP_MAX_REQUEST_CHARS` | `200` | 一文の最大文字数 |
| `MW_WORKSHOP_MAX_BODY_BYTES` | `32768` | リクエスト本文の上限 |
| `MW_WORKSHOP_CALL_TIMEOUT_MS` | `60000` | モデル呼び出し 1 回の制限時間 |
| `MW_WORKSHOP_REQUEST_TIMEOUT_MS` | `180000` | 生成の依頼全体の制限時間 |
| `MW_WORKSHOP_PREPARE_TIMEOUT_MS` | `150000` | モデル読み込みの制限時間。依頼全体の制限時間は超えません |
| `MW_WORKSHOP_STATS` | `.local/workshop-stats.jsonl` | 統計ファイル |

API キーはサービスのプロセスの中でだけ使います。ログには書かず、ブラウザーにも返しません。統計は依頼 1 件につき 1 行（結果、直した回数、段階ごとの時間）で、書いた一文と人物の情報は記録しません。

## コマンド

| コマンド | |
|---|---|
| `npm run dev:workshop` | ゲームと工房のサービス |
| `npm run dev` | ゲームだけ。工房は「サービスが使えません」と表示されます |
| `npm run build`、`npm run preview` | 本番ビルドとそのプレビュー。本番ビルドは工房のサービスにつながりません |
| `npm test` | ユニットテスト |
| `npm run e2e` | Playwright の E2E テスト（先に `npx playwright install chromium`） |
| `npm run typecheck`、`npm run lint` | 型チェックと ESLint |
| `npm run workshop-stats` | 工房の統計をまとめて表示 |
| `MW_WORKSHOP_ACCEPTANCE=1 npm run workshop-acceptance` | ローカルのモデルで、決まった 10 件の依頼をひととおり流す |
| `npm run inspect-asset -- <ファイル> [--json]` | GLB の構造を見る |

## GLB の中身を見る

```sh
npm run inspect-asset -- path/to/character.glb
```

コンテナー、メッシュと三角形の数、テクスチャ、ボーン、クリップごとの名前・長さ・ループするか・水平移動があるか、バウンディングボックスを表示します。読むのはそのファイル 1 つだけで、ネットワークには出ず、ファイルも書きません。計算できなかった項目は 0 で埋めずに、「未計算」と理由を表示します。`--json` を付けると JSON で出力します。

## 自分のキャラクターでテストを流す

```sh
MW_ASSET_DIR=<キャラクターのファイルを置いたフォルダ> npm run e2e -- tests/e2e/real-assets.spec.ts
```

フォルダの中のモデルを 1 つずつ読み込んで、スクリーンショットを撮ります。フォルダは読むだけで、プロジェクトにはコピーしません。`MW_ASSET_DIR` を指定しなければ、このテストはスキップされます。

## 開発用の URL パラメーター

開発モードでだけ使えます。

| パラメーター | |
|---|---|
| `?level=meadow`、`test-a`、`test-b` | 手作りのマップを直接開く |
| `?level=gen-1`、`gen-2`、`gen-3` | 生成して固定した 3 つのステージを直接開く |
| `?view=fixtures` | コードで作ったテスト用モデルを見る |
