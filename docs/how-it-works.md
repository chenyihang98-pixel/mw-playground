# レベル工房のしくみ

一文を書くとステージができる。その裏で、どこをモデルに任せて、どこをプログラムでやっているかを書きます。[README](../README.md) の図の続きです。

## モデルに書かせるのは仕様書だけ

モデルには座標を書かせていません。壁にめり込まない、宝石に歩いて届く、守衛の巡回ルートが通れる。こういう幾何の条件は、プログラムで作って検査したほうが確実です。モデルには、言葉を限られた選択肢に置き換えるところだけを任せました。

モデルが書く「ステージ仕様書」の中身はこれだけです。

| 項目 | 選択肢 |
|---|---|
| マップの大きさ | 小 / 中 / 大 |
| 障害物の量 | 少なめ / ふつう / 多め |
| 高台の数 | 0〜4 |
| 宝石の数と置き方 | ばらばら / 端のほう / 高台の上だけ / かたまり |
| 守衛の数と巡回 | 周回 / 往復 |
| 難しさの目安 | ゆったり / ふつう / きつめ |
| 見た目 | 草・砂・雪 × 昼・夕暮れ・夜 × 晴れ・霧・雨 |
| 登場人物 | 名簿の誰を、仲間にするか守衛にするか。ひとことのセリフ付き |
| タイトルと冒頭の文 | 自由に書ける短い文 |

JSON Schema で出力させて、受け取ったあと zod でもう一度確かめます。余分な項目は受け付けないので、座標や制限時間をモデルが書き足しても入りません。

## Schema では書けないルール

型と範囲は Schema で縛れますが、組み合わせのルールは別に検査しています。

| マップ | 宝石 | 守衛 |
|---|---|---|
| 小 | 2〜5 個 | 1 人まで |
| 中 | 3〜7 個 | 2 人まで |
| 大 | 4〜9 個 | 3 人まで |

- 宝石を「高台の上だけ」にするなら、高台 1 つにつき 2 個まで
- 仲間は 3 人まで
- 登場させられるのは、依頼のときにチェックを入れた人物だけ。役割も許可したものだけです

## 流れ

LangGraph のグラフはこの 6 つのステップです（`server/graph.ts`）。

1. **依頼を読む**：必要だとモデルが判断すれば、名簿ツールを呼びます
2. **仕様書を書く**：構造化出力
3. **検査する**：型と範囲、組み合わせのルール、人物と役割
4. **配置を作って検査する**：シードから毎回同じ結果になる生成器と、それとは別に書いた検査器
5. **プレビュー**：ここで止まって、プレイヤーの返事を待ちます
6. **保存**：確定されたら再開して保存

## うまくいかなかったとき

失敗の種類で扱いを分けています。

- **仕様書がルール違反**：どの項目がなぜ駄目かを添えてモデルに返します。仕様書を書けるのは合計 3 回（最初の 1 回と修正 2 回）
- **置ききれない、遠すぎる**：まずプログラム側で何度か作り直し、1 回だけ条件を調整します。それでも駄目ならモデルに返します
- **生成器が作った配置を検査器が拒否した**：これはプログラムのバグです。モデルには返さず、エラーにします
- **3 回とも駄目、または時間切れ**：内蔵ステージに切り替えて、理由と、依頼とどこが違うかを表示します

## プレビューと確定

プレビューのステップでは LangGraph の interrupt で処理を止め、確定されたら `Command({ resume })` で再開します。

- 確定のときにモデルは呼びません。保存されるのは、プレビューで見ていた配置そのものです
- 確定を続けて 2 回押しても、保存は 1 回だけです
- 確定の返事を待っている間に破棄や作り直しをしたら、遅れて届いた確定の結果は捨てます
- 確定前のプレビューはサービスのメモリー（MemorySaver）にあります。サービスを再起動すると消えるので、画面に作り直しの案内が出ます

再開すると、interrupt のあるステップは頭からもう一度実行されます。なので、このステップは止まる前に計算しかしていません。

## 名簿ツール

モデルが呼べるツールは `lookup_roster` の 1 つだけで、読み取り専用です。

- 呼ぶと、今回の依頼でチェックを入れた人物の一覧（表示名と、許可された役割）が返ります。条件での絞り込みはしていません
- 呼ぶかどうかはモデルが決めます
- ブラウザーから送るのは、人物の ID、表示名、許可した役割だけです。モデルのファイルは送りません

## 例：差し戻し

依頼は「小さいマップ、守衛 2 人、宝石はできるだけ多く」。

1. 1 回目の仕様書：`tier: small, guards: 2, collectibles: 5`
2. 検査で不合格。モデルにはこう返りました：「small マップの守衛は 1 人まで。いまは 2 人。守衛を減らすか、マップを大きくする」
3. 2 回目の仕様書：`tier: medium, guards: 2, collectibles: 7`。検査を通ってプレビューへ

検査は通りましたが、頼んだ「小さいマップ」は中サイズに変わっています。ルールを通すことと、頼まれたとおりにすることは別なので、結果は分けて記録しました。

## 例：ツール呼び出し

依頼は「装甲女兵を守衛に。守衛は 1 人でいい。中くらいのマップ」。

1. モデルが `lookup_roster` を呼ぶ
2. ツールが「r1：装甲女兵、仲間か守衛にできる」と返す
3. モデルが仕様書に `cast: [{ personId: "r1", role: "guard" }]`、`guards: 1` と書く
4. サービスが `r1` を本当の人物 ID に戻す

名簿の一覧は仕様書を書くときのプロンプトにも入れてあります。なので「人物を正しく選べた」だけでは、ツールを呼んだ証拠にはなりません。呼び出しの記録が残っているのがこの 1 回です。

## 試した 8 回

2026 年 11 月、Windows 11、RTX 5080（16 GB）、Ollama 0.40.16、qwen3.5:9b-q4_K_M。依頼の原文は中国語で、下は訳です。

| 依頼 | 結果 | 先に決めた条件 | 時間 |
|---|---|---|---|
| 小さいマップ、宝石 4 つを地面に散らして、守衛なし | 1 回で通過 | 3 / 3 | 8.2 秒（モデルの読み込み 5.9 秒を含む） |
| 砂漠の夕暮れ、霧、中くらいのマップ | 1 回で通過 | 3 / 3 | 2.2 秒 |
| 星璇を仲間にして、草原、昼 | 1 回で通過 | 2 / 2 | 2.6 秒 |
| 装甲女兵を守衛に。守衛は 1 人でいい。中くらいのマップ | 1 回で通過、ツールを 1 回呼んだ | 3 / 3 | 3.3 秒 |
| 大きいマップ、高台 3 つ、宝石は高台の上だけ、全部で 6 個 | 1 回で通過 | 3 / 3 | 2.2 秒 |
| 中くらいのマップ、守衛 2 人が往復で巡回、雨の夜 | 1 回で通過 | 3 / 3 | 2.3 秒 |
| 小さいマップ、守衛 2 人、宝石はできるだけ多く | 修正 1 回で通過 | 数えない（「小さいマップ」が守られなかった） | 3.7 秒 |
| 晴れた草原、小さいマップ、宝石 3 つを地面に、守衛なし、星璇についてきてもらう | 1 回で通過 | 3 / 3 | 8.3 秒（モデルの読み込み 4.2 秒を含む） |

- 最後の 1 回はブラウザーの画面から通しました。キャラクターの読み込み、生成、確定、宝石を全部集めるまでのプレイ、再読み込みしてもステージが残っていること、までです。プレイ中のキー入力はスクリプトから送っています
- 8 回とも、プレビューと保存後の配置は同じでした。確定にかかったのは 2〜5 ミリ秒です
- 長く使っていなかったあとに、最初の依頼だけ 1 分近くかかったことが 1 回あります。それ以来、モデルの読み込みは生成とは別に時間を計っています

1 回ごとの依頼、仕様書、結果は [evidence/workshop-20261116](evidence/workshop-20261116/) にあります（中国語）。

## なぜ LangGraph か

ふつうの関数でも書けます。状態グラフにしたのは、戻る場所が 2 つあるからです。ルール違反で「仕様書を書く」に戻るところと、プレビューで止まって確定のあとに続きから動くところ。その代わり、再開のときにステップが頭から実行し直される、といったフレームワークの決まりを知っておく必要があります。

## やっていないこと

- 確定前のプレビューを、サービスの再起動をまたいで残すこと
- 複数の依頼を同時にさばくこと
- 名簿ツールでの条件検索
- 実際の OpenAI 互換サービスでの動作確認（偽サーバーで試しただけです）

## コードの場所

| ファイル | 中身 |
|---|---|
| `server/graph.ts` | グラフ本体。差し戻しと内蔵ステージへの切り替えもここ |
| `server/prompts.ts` | プロンプト |
| `server/workshop.ts` | 生成・確定の入り口と、モデルの読み込み |
| `server/roster.ts` | 名簿の一覧と、役割の検査 |
| `src/game/level/gen/brief.ts` | 仕様書の Schema と組み合わせのルール |
| `src/game/level/gen/generator.ts`、`checker.ts` | 配置の生成器と検査器 |
