# 项目约定

后续每个任务开始前都要先读这份文件。改约定时在这里改，并在 `docs/status.md` 对应任务的一节里写明。

## 依赖

- 所有依赖都写确切版本，不带 `^` 或 `~`。用 `npm install --save-exact`（或 `-E`）添加。
- 只加任务要求的依赖。确实需要别的依赖时，在送审说明里写明理由。
- 改依赖（新增、删除、升级）的提交必须同时提交锁文件摘要：
  `npm run -s lock-summary -- <任务起点> HEAD > docs/deps/<任务编号>-lock-summary.md`，
  在依赖定下来、锁文件提交之后生成，内容必须与候选提交里的锁文件一致（审查方会重跑核对）。
- 安装用 `npm ci`；不要手改 `package-lock.json`。

## 锁文件为什么设 `-diff`

`.gitattributes` 里有 `package-lock.json -diff`。锁文件动辄上万行，展开在 diff 里会挤占审查材料的大小上限，而且逐行看锁文件很难看出要点。设了 `-diff` 后，审查材料里只显示“锁文件有变化”；锁文件的变化统一看 `lock-summary` 生成的摘要（新增、删除、升级、来源主机、缺 integrity、安装脚本）。`-diff` 只影响 diff 的显示，`git show` 仍能读出完整内容。

## 换行符

- 所有文本文件用 LF。`.gitattributes` 的第一条是 `* text=auto eol=lf`，工作区检出也是 LF。
- 送审前确认 `git diff --stat <起点>..HEAD` 和加上 `--ignore-cr-at-eol` 的结果一致（一致说明没有 CRLF 混进来）。
- 二进制类型（`*.glb`、`*.png`、`*.jpg`、`*.ktx2` 等）在 `.gitattributes` 里标为 `binary`。

## 测试

- `npm run typecheck`、`npm run lint`、`npm test`、`npm run e2e` 都要通过。
- 测试跑完后工作区必须干净：`git status` 里没有未跟踪的文件，也没有修改。测试输出只能写到已被忽略的目录（`test-results/` 等）或系统临时目录。
- 测试里创建的临时目录和文件只放在系统临时目录下，由创建它的测试清理。
- 测试本身不联网，不下载外部资源。测试用的模型由 `src/asset/fixtures/` 的代码生成。
- e2e 由 Playwright 的 `webServer` 自己起停服务（固定端口、`strictPort`、不复用已有服务）；不要依赖手动启动的后台进程。

## 测试钩子

- 测试钩子（`window.__MW_TEST__`）只在开发和测试模式下存在，生产构建里没有。
- 钩子只能做这几件事：观察状态、设随机种子、选关卡或夹具。
- 钩子不能代替实际游玩：不能直接改游戏状态（位置、血量、胜负等），不能跳过输入、物理或 AI。需要验证玩法时，通过真实的输入事件驱动。

## 玩法和模拟（P2 起）

- 所有角色共用的玩法参数（胶囊、速度、跳跃、高台高度、坡度、守卫扣时和冷却、收集半径、模拟步长）只在 `src/game/spec.ts` 定义。控制器、碰撞、守卫、关卡校验，以及以后的生成器和检查器都从这里取值，不各写各的常数。
- 关卡只通过 `src/game/level/schema.ts` 的 zod 布局加载（`parseLevel`）；语义校验 `layoutProblems` 可以单独复用。
- 模拟（`src/game/sim/`）、关卡（`src/game/level/`）和规格是纯模块：按固定步长推进，不读墙钟、不用随机数，不依赖 three、DOM 或渲染 / 界面 / 输入代码。ESLint 对这几个目录强制检查。渲染层只读模拟状态。
- 角色的视觉模型挂在外层节点（跟随物理胶囊）下的 `model-slot` 里，和物理胶囊分开。

## 导入（P3 起）

- 导入的各项上限和阈值只在 `src/import/limits.ts` 定义；改上限时同时改 docs/status.md 里的表。
- 导入的片段按“文件内容的 SHA-256 + 片段序号”标识，名字只用来显示；手动设置按序号保存。
- 原片段永远不改：锁定水平位移等处理只生成副本。
- 每个实例用 `SkeletonUtils.clone` 复制，有自己的骨骼和 AnimationMixer；几何、材质、贴图由资产统一释放。
- 提示文字只说“本版不支持”，不推断模匠会不会导出某种格式。

## 名册（P4 起）

- 名册的上限（人物数、同伴数、显示名长度）和分工只在 `src/roster/config.ts` 定义；改上限时同时改 docs/status.md 里 P4 一节。同伴跟随的距离、阈值和时长在 `SPEC.companion`。
- 存储只保存原文件和设置（键是文件内容的 SHA-256，片段设置按“SHA-256#片段序号”），不保存加载后的对象或归一化结果；恢复时一律重新走 `importModel`。
- 存储格式带版本号（`src/roster/format.ts` 的 `RECORD_VERSION`）。改格式时升版本号，并写清旧版本记录怎么处理；读到认不出的版本或损坏的记录时提示并跳过，不覆盖它们。
- 存储层通过 `RosterStore` 接口访问：浏览器里用 IndexedDB，单元测试用内存实现。存储失败只给提示，不能让游戏停下。
- 守卫人物只换关卡里守卫的外观，不改守卫的数量和路线；同伴只和地图碰撞，不影响胜负。

## 关卡生成（P5 起）

- 关卡说明书（`src/game/level/gen/brief.ts`）只描述“想要什么样的关卡”，不含坐标和时间限制。组合冲突返回具体、能照着改的原因，不悄悄改值。说明书的 schema 带 `schemaVersion`，P8 共用。
- 说明书的范围、档位、生成器的尺度、检查器的网格、难度系数和时间上下限只在 `src/game/level/gen/config.ts` 定义；改值时同时改 docs/status.md 的 P5 一节。
- 生成器、检查器、时间推算都在 `src/game/level/gen/`，属于纯模块（ESLint 禁止 Math.random、墙钟、three、DOM）。随机数只来自种子；种子、说明书和生成器版本相同时，布局也相同。生成规则变了就把 `generatorVersion` 加 1。
- 检查器独立于生成器：只用布局本身、P2 的 schema / layoutProblems 和几何函数，不用生成器内部的中间结果。判定必须保守（判为能走到的，实际一定能走到）。生成器做出了检查不通过的布局是程序缺陷，直接报出来，不用重试掩盖。
- 已保存和内置的生成关卡以冻结的布局和规则为准：加载时不重新生成，也不重算时间。存储格式带版本号，与名册分库（`mw-playground-levels`）。
- 对外只说“空间与规则检查通过，难度为估计”，不说“任何玩家都能在限时内通关”。

## 资产

- 真实资产（模匠导出的角色、其他模型和贴图）不进仓库，放在项目外。
- 仓库里不提交 `.glb` 等模型文件；测试需要的 GLB 由代码生成。

## 界面和视觉（P6 起）

- 界面的颜色、字号、间距、圆角、图标和通用组件都用 `src/ui/theme.css`、`src/ui/icons.ts`、`src/ui/dom.ts` 里已有的，约定见 [design.md](design.md)。新增界面不另写一套。
- 关卡选择、名册、导入卡片这类主面板交给 `src/ui/panels.ts` 管理，同时只显示一个；新的主面板也注册到这里。
- 不用外部资源：字体用系统字体栈，图标用内联 SVG，音效用 WebAudio 合成，贴图用代码画。

## 界面语言（F6 起）

- 浏览器里看得到的固定文字一律写进 `src/i18n/messages/` 的三份词典（zh、ja、en，键和占位名相同），代码里用 `t('键', { 参数 })` 取。不在代码里直接写界面文字。
- 中文词典是原文；改中文文字时三份词典一起改。日语、英语的用词见 docs/status.md 的 F6 一节。
- 用户数据和生成的文字（文件名、人名、已保存关卡的标题、模型写的文字、工坊服务写的说明）原样显示，所在元素标 `data-i18n-raw`（`src/ui/raw.ts`）。
- 服务端发给模型的文字、命令行输出和日志保持中文：Node 里不决定语言，一直是 zh。
- F7 起，工坊的生成请求带界面的语言（`lang`），健康检查带 `?lang=`。服务端不切换全局语言，用 `translator(lang)` 取指定语言的文字，交给需要它的模块（说明书校验、检查器、流水线、`diff.ts` 等的 `tr` 参数）。
  - 给玩家看的说明（程序调整、主要差别、修复记录、回退原因、模型不能用的原因）按请求的语言写；统计和日志里的原因仍是中文。
  - 发给模型的内容一律中文，只有 ja、en 请求的写说明书的系统提示改两处（`server/prompts.ts`）。zh 请求和 F7 之前逐字节相同（`tests/data/workshop-texts-zh.json`）。
- `tests/unit/i18n-source-scan.test.ts` 扫描 src 下的字符串字面量，含汉字或假名的只能出现在中文词典、日语词典和带理由的白名单里。

## 关卡工坊的本机服务（P8 起）

- 服务代码在 `server/`，用 `node:http`，由 `tsx` 运行，只监听 127.0.0.1（地址不做成配置）。不加 HTTP 框架。
- 生成和检查直接调用 P5 的纯模块（`src/game/level/gen/`、`src/game/levels/`），不复制代码，也不为了让模型的输出通过而改检查规则。
- 浏览器和服务之间的接口只在 `src/workshop/protocol.ts` 定义，请求和响应都用 zod 校验。
- 模型的输出只经结构化输出和 zod 校验进入流程；模型要求的工具调用只执行列出的只读工具。
- 密钥只从环境变量读，只在服务进程里使用：不写日志（日志逐行脱敏）、不进错误信息、不返回给浏览器、不进统计。测试里的假密钥写成 `fake-key-1` 这样一看就是假的：不用 OpenAI、GitHub 等真实密钥的前缀，不写 JWT 样式的字符串，Bearer 后面的值少于 16 个字符。
- 本机模型失败时不自动切换到外部接口。外部供应商在用户自己配好密钥试过之前，一律写“未验证”。
- 关卡由浏览器保存，服务端不存关卡；检查点只用进程内存。
- 健康检查和提供方的可用性检查不加载模型（只打开页面的人不应该被占掉显存）。真的要生成时，在第一次调用模型之前用提供方的 `prepare` 加载模型（F2）；加载有自己的超时，不算在单次模型调用的超时里。

## 仓库内容

- 仓库里不能出现密钥、令牌、个人的绝对路径（例如用户目录、某台机器上的项目路径）和个人邮箱。示例路径用相对路径或占位符；测试里需要邮箱时用 `example.invalid` 域名。

## 状态记录

- `docs/status.md` 每个任务写一节（标题用任务编号）。每节分开写“运行过的检查和结果”和“未运行或未验证”，后者写明原因和由谁在什么时候补做。
