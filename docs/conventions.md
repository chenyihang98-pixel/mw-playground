# 项目约定

后续每个任务开始前都要先读这份文件。改约定时在这里改，并在 `docs/status.md` 对应任务的一节里写明。

## 依赖

- 所有依赖都写确切版本，不带 `^` 或 `~`。用 `npm install --save-exact`（或 `-E`）添加。
- 只加任务要求的依赖。确实需要别的依赖时，在送审说明里写明理由。
- 改依赖（新增、删除、升级）的提交必须同时提交锁文件摘要：
  `npm run -s lock-summary -- <任务起点> HEAD > docs/deps/<任务编号>-lock-summary.md`，
  在依赖定下来、锁文件提交之后生成，内容必须与候选提交里的锁文件一致（审查方会重跑核对）。
- 安装用 `npm ci`；不要手改 `package-lock.json`。

## 锁文件为什么设 `-diff`

`.gitattributes` 里有 `package-lock.json -diff`。锁文件动辄上万行，展开在 diff 里会挤占审查材料的大小上限，而且逐行看锁文件很难看出要点。设了 `-diff` 后，审查材料里只显示“锁文件有变化”；锁文件的变化统一看 `lock-summary` 生成的摘要（新增、删除、升级、来源主机、缺 integrity、安装脚本）。`-diff` 只影响 diff 的显示，`git show` 仍能读出完整内容。

## 换行符

- 所有文本文件用 LF。`.gitattributes` 的第一条是 `* text=auto eol=lf`，工作区检出也是 LF。
- 送审前确认 `git diff --stat <起点>..HEAD` 和加上 `--ignore-cr-at-eol` 的结果一致（一致说明没有 CRLF 混进来）。
- 二进制类型（`*.glb`、`*.png`、`*.jpg`、`*.ktx2` 等）在 `.gitattributes` 里标为 `binary`。

## 测试

- `npm run typecheck`、`npm run lint`、`npm test`、`npm run e2e` 都要通过。
- 测试跑完后工作区必须干净：`git status` 里没有未跟踪的文件，也没有修改。测试输出只能写到已被忽略的目录（`test-results/` 等）或系统临时目录。
- 测试里创建的临时目录和文件只放在系统临时目录下，由创建它的测试清理。
- 测试本身不联网，不下载外部资源。测试用的模型由 `src/asset/fixtures/` 的代码生成。
- e2e 由 Playwright 的 `webServer` 自己起停服务（固定端口、`strictPort`、不复用已有服务）；不要依赖手动启动的后台进程。

## 测试钩子

- 测试钩子（`window.__MW_TEST__`）只在开发和测试模式下存在，生产构建里没有。
- 钩子只能做这几件事：观察状态、设随机种子、选关卡或夹具。
- 钩子不能代替实际游玩：不能直接改游戏状态（位置、血量、胜负等），不能跳过输入、物理或 AI。需要验证玩法时，通过真实的输入事件驱动。

## 资产

- 真实资产（模匠导出的角色、其他模型和贴图）不进仓库，放在项目外。
- 仓库里不提交 `.glb` 等模型文件；测试需要的 GLB 由代码生成。

## 仓库内容

- 仓库里不能出现密钥、令牌、个人的绝对路径（例如用户目录、某台机器上的项目路径）和个人邮箱。示例路径用相对路径或占位符；测试里需要邮箱时用 `example.invalid` 域名。

## 状态记录

- `docs/status.md` 每个任务写一节（标题用任务编号）。每节分开写“运行过的检查和结果”和“未运行或未验证”，后者写明原因和由谁在什么时候补做。
